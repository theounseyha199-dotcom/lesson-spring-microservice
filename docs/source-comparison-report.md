# Code comparison and selective replacement

Reference: `/home/seyha/data/istad-ite-platform`. Current project: `istad-ite-1`.

Reviewed 107 differing text files at matching paths (excluding IDE metadata and binary wrappers), plus the differently packaged IAM, gateway, Swagger and relocated business implementations. Identical files do not need replacement. Evaluated behavior, completeness, schema correctness, tests and compatibility rather than choosing one repository wholesale.

## Result

Applied reference improvements in 14 production files: 10 complete file replacements and 4 compatible adaptations. The current project has the stronger working customer/order flows; the reference has useful low-level mapping and domain improvements.

## Differently located implementations

- IAM: retained the current package, account flags, role-derived permissions, idempotent user initialization and token audience customization. The reference uses a separate entity/schema model, logs authentication objects to stdout, and its seed user leaves enabled/account flags false. Its JDBC authorization/consent persistence is useful, but depends on additional tables and warrants a coordinated auth migration rather than overwriting the existing security class alone.
- Gateway: both entrypoints start the same application; package relocation is not an improvement. Preserve the current configurable frontend URL and route order.
- Swagger: preserve the current configuration package and its tested auto-configuration import; the reference annotation adds demo-specific text.
- Business: current service already has modular business creation, persistence and endpoints; reference is a single-module demo returning random business IDs.
